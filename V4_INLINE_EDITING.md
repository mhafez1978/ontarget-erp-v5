# V4 Inline Editing Feature

## Overview

A new inline editing system that allows customers to click on website elements and edit them directly in the preview, without using the Content Wizard.

## Problem Solved

1. **Duplicate Footer**: V4 websites were showing two footers - one generated by V4 (nice styling) and one from StorefrontLayout (narrow). Fixed by adding `hideFooter` prop.
2. **Content Wizard Export Not Working**: Instead of fixing the broken export, we created a better editing experience with inline editing.

## How It Works

### 1. Edit Mode Toggle

- In the V4 preview, click "Edit Mode" button
- All editable sections get a dashed outline and "Click to edit" badge
- Only available after website is saved (needs `websiteId`)

### 2. Click to Edit

- Click any section to open the editor dialog
- Automatically detects editable fields:
  - Heading (h1, h2 tags)
  - Subheading (subtitle/lead paragraph)
  - Description (main content paragraph)
  - Button text (CTA buttons)
  - Button link (href for CTA)

### 3. Save & Publish

- Click "Save Changes" to update the section
- Preview automatically refreshes with changes
- Changes are saved to the database immediately
- Click "Publish" to make changes live on the storefront

## Technical Implementation

### API Endpoints

#### POST `/api/storefront/v4/update-section`

Updates a specific section of a V4 website.

**Request:**

```json
{
  "websiteId": "string",
  "pageSlug": "home", // optional, defaults to "home"
  "componentIndex": 0, // which section to update
  "updates": {
    "heading": "New Title",
    "subheading": "New Subtitle",
    "description": "New description text",
    "ctaText": "New Button Text",
    "ctaLink": "/new-link"
  }
}
```

**Response:**

```json
{
  "success": true,
  "message": "Section updated successfully",
  "updatedComponent": { ... }
}
```

#### POST `/api/storefront/v4/publish`

Makes a V4 website active and visible on the storefront.

**Request:**

```json
{
  "websiteId": "string"
}
```

**Response:**

```json
{
  "success": true,
  "message": "Website published successfully",
  "publishedAt": "2026-01-05T..."
}
```

### Components

#### `V4InlineEditor`

Client component that handles the editing UI.

**Props:**

- `websiteId` - ID of the website being edited
- `pageSlug` - Which page to edit (default: "home")
- `componentIndex` - Which component/section on the page
- `isEnabled` - Whether edit mode is active
- `onSave` - Callback after successful save

**Features:**

- Detects clicks on editable elements
- Opens dialog with form fields
- Validates and saves changes
- Refreshes preview automatically

#### `EditableSection`

Wrapper component that makes sections visually editable.

**Props:**

- `children` - The section content
- `componentIndex` - Section index for data attributes
- `isEditMode` - Whether to show edit UI

**Features:**

- Adds `data-component-index` attribute
- Shows dashed outline in edit mode
- Adds "Click to edit" badge
- Hover effects with ring styling

### Database Changes

No schema changes required! Updates are stored in the existing `v4Website.data` JSON field.

Each component gets metadata tracking:

```typescript
{
  ...component,
  metadata: {
    ...existingMetadata,
    lastEditedAt: "2026-01-05T...",
    editedBy: "userId"
  }
}
```

## HTML Parsing Strategy

The inline editor uses regex patterns to intelligently update HTML:

1. **Heading**: Finds `<h1>` or `<h2>` tags and replaces content
2. **Subheading**: Finds paragraphs with `subtitle`, `subheading`, or `lead` classes
3. **Description**: Finds main content paragraphs (excluding buttons)
4. **CTA Text**: Finds button/link tags with `button`, `btn`, or `cta` classes
5. **CTA Link**: Updates href attribute of CTA links

### Example:

Original HTML:

```html
<h1 class="text-4xl">Old Title</h1>
<p class="text-lg lead">Old subtitle</p>
```

After editing heading to "New Title":

```html
<h1 class="text-4xl">New Title</h1>
<p class="text-lg lead">Old subtitle</p>
```

## User Flow

### For Customers:

1. Generate a V4 website using AI chat
2. Review the preview
3. Click "Edit Mode" to enable editing
4. Click on any section to open editor
5. Change text, headings, buttons, links
6. Click "Save Changes"
7. Preview updates automatically
8. Click "Publish" when ready to go live

### Benefits:

- ✅ No need to understand Content Wizard
- ✅ Direct, intuitive editing
- ✅ Immediate visual feedback
- ✅ No page reloads (uses optimistic updates)
- ✅ Preserves AI-generated design and styling
- ✅ Can edit multiple sections independently

## Known Limitations

1. **Edit Mode Only After Save**: Must save the generated website before editing is enabled
2. **Home Page Only**: Currently only supports editing the home page
3. **Text Fields Only**: Can't edit images, colors, or layout yet
4. **Regex Parsing**: May not catch all HTML patterns (especially custom/unusual markup)
5. **No Undo**: Once saved, changes can't be undone (except by regenerating)

## Content Wizard Status

The "Export to Content Wizard" button still exists and attempts to work, but:

- Known to have issues with field persistence
- Kept intact as requested
- Inline editing provides better UX alternative
- May be deprecated in future in favor of inline editing

## Support & Troubleshooting

### "Edit Mode button is disabled"

- Website must be saved first (needs ID from database)
- Click "Save" or generate website before editing

### "Changes aren't saving"

- Check console for API errors
- Verify user has access to the company
- Ensure website belongs to the user's company

### "Can't find editable fields"

- Component HTML may not match expected patterns
- Check browser console for parsing warnings
- May need to add custom data attributes to generated HTML

### "Preview doesn't refresh after save"

- Check network tab for API response
- Clear browser cache
- Try hard refresh (Cmd+Shift+R)
